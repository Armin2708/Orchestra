Date: 2026-08-03

Base: `7c147c4ccccb11bb89850f3119cdb23859c81916`

## Asked

Make the Codex CLI path closer to plug-and-play without weakening the exact-version, credential,
billing, or provider-acceptance boundaries.

## Delivered

- Moved the exact Codex implementation candidate from CLI 0.144.6 to 0.146.0.
- Regenerated and recorded the experimental app-server TypeScript contract: 701 files with SHA-256
  `62ba8908d54dd936875013976300421b2b47055c450adb36c84ab68eebb3a1e9`.
- Compared 0.144.6 and 0.146.0 generated bindings. Orchestra's consumed stable request shapes are
  unchanged; the relevant response changes are additive. The narrow protocol types continue to
  retain unknown fields and methods.
- Added `npm run check:codex-app-server`, a credential-free live probe that starts app-server with a
  new signed-out temporary `CODEX_HOME` and isolated home/XDG directories. It checks initialize,
  account response shape, model list, read-only thread start/read, and unsubscribe. It does not read
  the operator's profile, log in, or start a model turn.
- Added the live probe to the existing exact-commit `codex-protocol` CI evidence gate.
- Retargeted the two-phase real acceptance harness to official `@openai/codex@0.146.0` while keeping
  the managed support claim blocked.

## Evidence

The current official Codex manual documents app-server as the deep-integration surface for
authentication, conversation history, approvals, and streamed events. It also states that generated
schemas are specific to the CLI version that produced them and that app-server remains experimental.
The same manual distinguishes ChatGPT subscription login from API-key, usage-priced login. Orchestra
therefore keeps exact protocol evidence separate from billing and credential acceptance.
